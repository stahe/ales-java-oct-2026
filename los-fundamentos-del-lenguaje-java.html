    3. Los fundamentos del lenguaje Java

    3.1. Introducción

    Comenzaremos tratando Java como un lenguaje de programación tradicional. Veremos las clases en el próximo capítulo. Un programa consta de dos cosas:

    • datos;
    • las instrucciones que los manipulan.

    Generalmente se procura separar los datos de las instrucciones:

    Todos los ejemplos de este capítulo son archivos fuente compactos: un único archivo llamado [.java], sin proyecto Maven, que se ejecuta con el comando [java Basics01.java]. El lanzador [java] compila entonces el archivo en memoria y lo ejecuta, sin producir un archivo [.class]. Esta capacidad se presentó en el capítulo 2, “Configuración del entorno de desarrollo”. Los ejemplos se encuentran en la carpeta [03-basics] del código del curso. Se ejecutan con el idioma y las convenciones del francés (la “configuración regional” fr-FR), tal como lo harían en una máquina con Windows en francés. Veremos que esto solo afecta a los números y las fechas con un formato específico: la conversión simple de un número de punto flotante a una cadena siempre usa el punto decimal.

    Comentarios:

    • El archivo no contiene ninguna declaración de clase, solo un método llamado [main]. Se trata de un archivo fuente compacto (Java 25). El propio compilador envuelve el contenido del archivo en una clase declarada implícitamente que lleva el nombre del archivo: [Basics01]. Esta característica se introdujo como preview en Java 21 hasta Java 24 antes de ser definitiva en Java 25;
    • Línea 3: el método [main] es el punto de entrada del programa: es este método el que ejecuta el lanzador [java] . A partir de Java 25, puede escribirse simplemente como [void main()], sin las palabras clave [public] y [static] y sin ningún parámetro. El cuerpo del método se encierra entre llaves;
    • línea 4: el método [println] de la clase [IO] (Java 25) escribe una línea en la pantalla;
    • Línea 6: la forma tradicional de la misma operación. [System] es una clase, [out] es uno de sus campos, que representa la salida estándar (la pantalla), y [println] es un método de este objeto. [IO.println(x)] es simplemente un atajo para [System.out.println(x)]. Usaremos [IO.println] en los archivos compactos y [System.out.println] en las clases normales, donde aparece en todo el código Java existente;
    • línea 8: [List] es una lista de cadenas de caracteres; las listas se tratarán en el capítulo 5. [List] pertenece al paquete [java.util]: un paquete agrupa clases relacionadas, igual que una carpeta agrupa archivos. El nombre completo de la clase es [java.util.List]. Puede usarse sin una instrucción import porque el archivo es un archivo compacto (véase más adelante);
    • línea 9: una lista se muestra con sus elementos entre corchetes;
    • cada instrucción termina con un punto y coma; las líneas que comienzan con // son comentarios, que el compilador ignora.

    • línea 4: en Java, todo el código pertenece a una clase. Aquí la clase se llama [Basics02]. Una clase declarada como [public] debe estar en un archivo con ese nombre: [Basics02.java];
    • línea 6: el método [main] es el punto de entrada del programa. Es [public] (accesible desde fuera de la clase, en particular mediante el lanzador [java]), [static] (se ejecuta sin necesidad de crear un objeto de la clase), no devuelve ningún resultado ([void]) y recibe los argumentos de la línea de comandos en el arreglo [args];

    • Línea 10: el método [Arrays.toString] construye una cadena a partir de los elementos de un arreglo.

    Los dos programas [Basics01.java] y [Basics02.java] son de naturaleza similar. Cuando encuentra un archivo compacto, el propio compilador genera una clase [final] con el nombre del archivo, cuyos métodos y campos son los escritos en el archivo. El archivo compacto es, por lo tanto, simplemente una versión abreviada de la forma estándar. Es adecuado para los programas pequeños de este capítulo; la forma estándar se vuelve necesaria en cuanto un programa contiene varias clases, lo que ocurrirá a partir del capítulo 4.

    Desde Java 25, el método [main] puede adoptar cuatro formas: [static void main(String[] args)], [static void main()], [void main(String[] args)], y [void main()]; si una clase contiene varias de ellas, el lanzador prefiere la que tiene el parámetro [String[]]. Las dos últimas formas son métodos de instancia: el lanzador crea primero un objeto de la clase y luego llama a su método [main]. La palabra clave [public] ya no es obligatoria.

    3.2.3. Importación automática del módulo java.base

    El programa [Basics01.java] usa la clase [List] sin la directiva [import java.util.List;]. Esto es posible porque el compilador agrega automáticamente la siguiente directiva a todo archivo compacto (Java 25):

    1
    import module java.base;

    Las clases de la biblioteca estándar de Java están organizadas en paquetes, que a su vez se agrupan en módulos. El módulo [java.base] es el módulo central: contiene los paquetes de uso más frecuente. La directiva [import module java.base;] importa de una sola vez todas las clases públicas de todos los paquetes exportados por este módulo, lo que equivale, entre otras cosas, a las siguientes directivas:

La clase [IO] forma parte del paquete [java.lang]: puede usarse en cualquier lugar.

    Los primeros ocho tipos de la tabla, cuyos nombres se escriben en minúsculas, son los tipos primitivos de Java. Todos los demás tipos son tipos de referencia: clases ([String], [BigDecimal], [Object]...), así como arreglos, enumeraciones, interfaces y records, que veremos más adelante. La diferencia es fundamental:

    • una variable de un tipo primitivo contiene directamente su valor;
    • una variable de un tipo de referencia contiene la dirección del objeto (su referencia), y el propio objeto se almacena en otra parte de la memoria.

    Un valor de un tipo primitivo no es un objeto: no tiene ni campos ni métodos. Sin embargo, cada tipo primitivo corresponde a una “clase envoltorio” del paquete [java.lang]: [Integer] para [int], [Double] para [double], [Character] para [char], y así sucesivamente. Un objeto [Integer] envuelve un valor [int]. Estas clases también ofrecen constantes y métodos útiles: [Integer.MAX_VALUE], [Integer.BYTES], [Integer.parseInt]... Desde Java 5, el compilador convierte automáticamente un tipo primitivo en su clase envoltorio (boxing) y viceversa (unboxing). Así, podemos escribir:

    1
    String typeName = Integer.valueOf(3).getClass().getName();

    El literal 3 es de tipo [int]. Como no tiene métodos, no podemos escribir [3.getClass()]: primero debemos envolverlo en un objeto [Integer] mediante [Integer.valueOf(3)]. Todo objeto tiene un método [getClass()] que devuelve un objeto que describe su clase; el método [getName()] de ese objeto devuelve el nombre completo de la clase, en este caso [java.lang.Integer].

    Java no tiene enteros sin signo, salvo el tipo [char] (16 bits). En cambio, las clases envoltorio ofrecen métodos que interpretan los bits de un entero como los de un número sin signo: [Integer.toUnsignedString], [Integer.parseUnsignedInt], [Integer.compareUnsigned], [Byte.toUnsignedInt]... Tampoco tiene un tipo decimal primitivo: los importes se calculan con la clase [BigDecimal] del paquete [java.math], de la que hablaremos un poco más adelante.

    En el código fuente, los números de punto flotante siempre se escriben con punto decimal. Desde Java 7, los enteros pueden escribirse en binario (con el prefijo [0b]) y los grupos de dígitos pueden separarse con el carácter _ para mejorar la legibilidad: [1_000_000] es el entero un millón. El sufijo L puede escribirse en minúscula, pero la l se parece demasiado al dígito 1. Por último, cuidado con una trampa heredada del lenguaje C: un entero escrito con un 0 inicial se interpreta como octal (base 8): 017 es igual a 15.

    Un literal de cadena puede contener secuencias de escape introducidas por el carácter \: "\n" representa el carácter de fin de línea y no la secuencia de los dos caracteres \ y n, "\t" representa una tabulación, "\"" representa unas comillas dobles y "\\" representa el propio carácter \. Para escribir la ruta de Windows c:\chap1\paragraph3, por lo tanto, debe escribir "c:\\chap1\\paragraph3". Java no tiene una cadena “sin procesar” (raw) en la que el carácter \ se interprete tal cual; sin embargo, las clases de archivos de Java también aceptan el separador / en Windows: "c:/chap1/paragraph3" designa el mismo archivo.

    Para construir una cadena a partir de varios valores, Java ofrece dos métodos:

    • la concatenación con el operador +: en cuanto uno de los dos operandos es una cadena, el otro se convierte en cadena;
    • los formatos: [String.format(format, value1, value2, ...)], o de forma equivalente [format.formatted(value1, value2, ...)] (Java 15), y para mostrar directamente, [System.out.printf(format, value1, ...)]. La cadena de formato contiene marcadores de posición que se reemplazan en orden por los valores siguientes: %s (cualquier valor convertido en cadena), %d (un entero), %f (un número de punto flotante), %.2f (un número de punto flotante con dos decimales), %x o %X (un entero en hexadecimal), %,d (un entero con separador de miles), %e (notación científica), %n (un salto de línea), %10s (una cadena alineada a la derecha en 10 caracteres), %-10s (alineada a la izquierda)... Los formatos numéricos siguen las convenciones del idioma del usuario.

    Java no admite las cadenas “interpoladas” que contienen expresiones entre llaves: una característica así (conocida como “string templates”) se propuso como preview en Java 21 y 22, pero luego se eliminó. La concatenación y el formato siguen siendo las únicas opciones.

    Desde Java 15, se puede escribir una cadena en varias líneas mediante un “bloque de texto”: comienza con tres comillas seguidas de un salto de línea y termina con tres comillas. Puede contener comillas sin escapar. Se elimina el espacio en blanco inicial común a todas las líneas (incluida la línea que contiene las comillas de cierre), lo que permite sangrar el texto junto con el código. Sin embargo, las secuencias de escape se interpretan igual que en una cadena normal: siempre se debe escribir \\ para obtener \. Los bloques de texto son muy útiles para escribir JSON, SQL o HTML.

    3.3.3. Declaración de datos

    3.3.3.1. Función de las declaraciones

    Un programa manipula datos caracterizados por un nombre y un tipo. Estos datos se almacenan en memoria. Cuando se compila el programa, el compilador asigna a cada dato una ubicación de memoria caracterizada por una dirección y un tamaño. Lo hace a partir de las declaraciones realizadas por el programador. Además, estas declaraciones permiten al compilador detectar errores de programación. Así, la operación [x = x * 2;] se señalará como un error si [x] es una cadena.

    3.3.3.2. Declaración de constantes

    En Java, una constante es una variable declarada con la palabra clave [final]: solo se le puede asignar un valor una vez. La sintaxis es la siguiente:

    1
    final type name = value;

    Una constante utilizada en todo el programa se declara fuera de los métodos, como un campo [static final] de la clase. Por ejemplo:

    1
    static final double VAT_RATE = 0.2;

    ¿Por qué declarar constantes?

    • El programa es más fácil de leer si a la constante se le da un nombre significativo;
    • es más fácil modificar el programa si hay que cambiar la “constante”. Así, si la tasa de IVA cambia a 0.25, la única modificación necesaria será en la instrucción que define su valor: [static final double VAT_RATE = 0.25;]. Si se hubiera usado 0.2 explícitamente en el programa, habría que modificar numerosas instrucciones.

    Por convención, en Java, el nombre de una constante [static final] se escribe en mayúsculas, con las palabras separadas por el carácter _: [VAT_RATE], [MAX_VALUE]. Una variable local también puede declararse como [final]; en ese caso, conserva un nombre normal. La palabra [const] está reservada en Java, pero no se utiliza.

    3.3.3.3. Declaración de variables

    Una variable se identifica por un nombre y se asocia a un tipo de datos. Java distingue entre mayúsculas y minúsculas: las variables [END] y [end] son diferentes. Por convención, el nombre de una variable comienza con minúscula, y cada palabra siguiente comienza con mayúscula: [priceExclTax], [nbChildren].

    Las variables pueden inicializarse al declararlas. La sintaxis para declarar una o varias variables es:

    1
    type variable1 = value1, variable2 = value2, ...;

    donde [type] es un tipo predefinido o un tipo definido por el programador. La inicialización es opcional; sin embargo, Java no permite usar una variable local a la que aún no se le ha asignado un valor (mensaje de error [variable x might not have been initialized]).

    Desde Java 10, también se puede omitir el tipo de una variable local usando la palabra clave [var] en lugar del tipo:

    1
    var variable1 = value1;

    El término [var] no significa que la variable no tenga un tipo específico: tiene el tipo del valor que se le asigna, determinado por el compilador. Aquí la inicialización es obligatoria para que el compilador pueda inferir el tipo. [var] solo puede usarse para variables locales (no para campos ni parámetros de métodos). Se usa cuando el tipo es evidente a partir del valor, en particular cuando el nombre de la variable es largo.

    3.3.4. Valores ausentes: null, clases envoltorio y Optional

    Una variable de un tipo primitivo, como [int], siempre contiene un valor. A veces es útil poder expresar la ausencia de un valor: una edad desconocida, un campo vacío en una base de datos. En esos casos se usa la clase envoltorio: una variable de tipo [Integer] es una referencia, que puede ser [null], es decir, “ningún objeto”.

    Cualquier variable de un tipo de referencia puede, de hecho, tener el valor [null]: en ese caso, no referencia ningún objeto. Intentar usar un miembro de esa variable, por ejemplo su método [length()], provoca un error en tiempo de ejecución, una [NullPointerException]: es el error más común en Java. Desde Java 15, el mensaje de error indica exactamente qué expresión se evaluó como [null]. El compilador de Java no distingue entre una referencia que puede valer [null] y una que no; las anotaciones como las del proyecto JSpecify ([@Nullable], [@NonNull]), que utilizan las herramientas de análisis, ayudan a paliar esta deficiencia, pero no las usaremos.

    Para indicar que un método puede no devolver nada, Java 8 agregó la clase [Optional<T>]: un objeto [Optional<String>] es una “caja” que contiene una cadena o está vacía. Se crea con [Optional.of(value)], [Optional.empty()], o [Optional.ofNullable(valueOrNull)]; se consulta con [isPresent()], [isEmpty()] (Java 11), [get()], [orElse(defaultValue)]... Las clases [OptionalInt], [OptionalLong], y [OptionalDouble] cumplen el mismo propósito para los tipos primitivos.

    3.3.6. Arreglos de datos

    Un arreglo de Java es un objeto que permite agrupar datos del mismo tipo bajo un único identificador. Se declara de la siguiente manera:

    1
    Type[] array = new Type[n];

    [n] es el número de elementos de datos que puede contener el arreglo. La sintaxis [array[i]] hace referencia al elemento de datos número i, donde i pertenece al intervalo [0, n-1]. Cualquier referencia al elemento [array[i]] donde i no esté en el rango [0, n-1] provoca una excepción [ArrayIndexOutOfBoundsException]. Al crearse, a cada elemento del arreglo se le asigna el valor predeterminado de su tipo: 0 para los números, [false] para los booleanos y [null] para los tipos de referencia. Un arreglo puede inicializarse al mismo tiempo que se declara:

    1
        int[] integers = new int[]{0, 10, 20, 30};

    o, de forma más simple, en una declaración:

    1
        int[] values = {0, 10, 20, 30, 40};

    Los arreglos tienen un campo [length] (sin paréntesis) que representa el número de elementos. Un arreglo no puede cambiar de tamaño después de crearse: para una colección que crece, se usa una lista (Capítulo 5). También se encuentra la notación [int integers[]], heredada del lenguaje C: se acepta, pero no se recomienda.

    Java no tiene verdaderos arreglos de dos dimensiones: un arreglo con dos índices es un arreglo de arreglos. La declaración

    1
    Type[][] array = new Type[n][m];

    crea un arreglo de [n] elementos, cada uno de los cuales es una referencia a un arreglo de [m] elementos: [n] filas y [m] columnas. La sintaxis [array[i][j]] hace referencia al elemento j de la fila i. [array.length] es el número de filas, y [array[i].length] es el número de elementos de la fila i. El arreglo también puede inicializarse al mismo tiempo que se declara:

    1
        double[][] reals = {{0.5, 1.7}, {8.4, -6}};

    Como cada fila es un arreglo independiente, las filas pueden tener longitudes distintas (esto se conoce como un arreglo "escalonado"). La declaración

    1
    Type[][] array = new Type[n][];

    crea un arreglo de n elementos, cada uno de los cuales es una referencia a un arreglo unidimensional. Estas referencias no se inicializan con la declaración anterior: tienen el valor [null].

    Java no ofrece índices contados desde el final del arreglo ni una notación para extraer un rango de elementos. El último elemento se escribe como [array[array.length - 1]], y el método [Arrays.copyOfRange(array, start, end)] devuelve un nuevo arreglo formado por los elementos con índices desde [start] (inclusive) hasta [end] (exclusive). La clase [java.util.Arrays] ofrece muchos otros métodos de utilidad: [toString], [deepToString], [sort], [fill], [equals], [copyOf]... Las listas, que son más flexibles, tienen los métodos [getFirst()] y [getLast()] desde Java 21.

    3.4. Instrucciones básicas de Java

    Hay dos tipos:

    • instrucciones básicas ejecutadas por la computadora;
    • instrucciones que controlan el flujo del programa.

    Las instrucciones básicas se entienden mejor al considerar la estructura de una microcomputadora y sus periféricos:

    • 1: lectura de información desde el teclado;
    • 2: procesamiento de la información;
    • 3: escritura de información en la pantalla.

    3.4.1. Escritura en la pantalla

    Hay varias instrucciones para escribir en la pantalla:

    1
2
3
    System.out.println(expression);
System.err.println(expression);
IO.println(expression);

    donde [expression] es cualquier dato que pueda convertirse en una cadena de caracteres para mostrarse en la pantalla. Todos los objetos Java tienen un método [toString()] que se usa para realizar esta conversión; los valores de tipos primitivos se convierten mediante [String.valueOf]. El método [print] hace lo mismo que [println] sin saltar a la línea siguiente, y el método [printf(format, value1, ...)] escribe el resultado con un formato específico.

    La clase [System] da acceso a dos flujos de escritura, sus campos estáticos [out] y [err], de tipo [PrintStream]:

    • [System.out.println()] escribe en el flujo [out], la salida estándar, que normalmente está asociada con la pantalla;
    • [System.err.println()] escribe en el flujo [err], la salida de errores, que normalmente también está asociada con la pantalla.

    La clase [IO] (Java 25) ofrece los métodos [println] y [print], que escriben en [System.out]. Los flujos [out] y [err] pueden redirigirse a archivos en tiempo de ejecución, como veremos en breve.

    3.4.2. Lectura de datos ingresados desde el teclado

    El flujo de datos del teclado se identifica mediante el campo [System.in], de tipo [InputStream]. Es un flujo de bytes, que no resulta muy cómodo de usar directamente. Durante mucho tiempo, para leer una línea de texto era necesario envolverlo en otros objetos:

    1
2
    BufferedReader keyboard = new BufferedReader(new InputStreamReader(System.in));
String line = keyboard.readLine();

    o utilizar la clase [Scanner] (Java 5). A partir de Java 25, la clase [IO] ofrece un método mucho más simple, [readln], en dos formas:

    1

String line = IO.readln("prompt: ");

    La línea escrita en el teclado, sin el carácter de fin de línea, se almacena en la variable [line] y luego puede ser procesada por el programa. La segunda forma muestra primero un mensaje de solicitud, sin saltar a la línea siguiente. Como hemos visto, [readln] devuelve [null] cuando el flujo de entrada se agota. El flujo [System.in] puede redirigirse a un archivo, igual que los flujos [out] y [err]. Por último, observe la clase [Console], obtenida a partir de [System.console()], cuyo método [readPassword] lee una contraseña sin mostrarla.

    3.4.4. Redirección de entrada/salida

    Windows, Linux y macOS reconocen tres dispositivos estándar:

    • el dispositivo de entrada estándar, que por defecto corresponde al teclado y está numerado como 0;
    • el dispositivo de salida estándar, que por defecto corresponde a la pantalla y está numerado como 1;
    • el dispositivo de error estándar, que por defecto corresponde a la pantalla y está numerado como 2.

    En Java, el flujo de escritura [System.out] escribe en el dispositivo 1, el flujo de escritura [System.err] escribe en el dispositivo 2, y el flujo de lectura [System.in] lee datos del dispositivo 0.

    Cuando se ejecuta un programa en una ventana de comandos, se puede especificar qué dispositivos serán el 0, el 1 y el 2 para el programa que se ejecuta. Después de los argumentos del programa, se pueden redirigir los dispositivos estándar de entrada y salida a archivos:

    Redirección
    Significado
    0<in.txt o <in.txt
    El flujo de entrada estándar n.º 0 se redirige al archivo in.txt. En el programa, el flujo [System.in] leerá por tanto sus datos del archivo in.txt
    1>out.txt o >out.txt
    redirige la salida n.º 1 al archivo out.txt. En el programa, el flujo [System.out] escribirá por tanto sus datos en el archivo out.txt
    1>>out.txt o >>out.txt
    Igual que lo anterior, pero los datos escritos se agregan al contenido actual del archivo out.txt
    2>err.txt
    redirige la salida n.º 2 al archivo err.txt. En el programa, el flujo [System.err] escribirá por tanto sus datos en el archivo err.txt
    2>>err.txt
    Igual que lo anterior, pero los datos escritos se agregan al contenido actual del archivo err.txt
    1>out.txt 2>err.txt
    Los dispositivos 1 y 2 se redirigen ambos a archivos

    3.4.5. Asignación del valor de una expresión a una variable

    Aquí nos interesa la operación [variable = expression;]. La expresión puede ser aritmética, relacional, booleana, de cadena, etc.

    3.4.5.1. Interpretación de la operación de asignación

    La operación [variable = expression;] es en sí misma una expresión que se evalúa de la siguiente manera:

    • se evalúa el lado derecho de la asignación: el resultado es un valor V;
    • el valor V se asigna a la variable;
    • el valor V es también el valor de la asignación, vista esta vez como una expresión.

    Por eso la operación [V1 = V2 = expression] es válida. Como el operador = se evalúa de derecha a izquierda, obtenemos [V1 = (V2 = expression)]. Se evalúa la expresión [V2 = expression] y su valor es V. Su evaluación provocó que V se asignara a V2. A continuación se evalúa el siguiente operador = como [V1 = V]. El valor de esta expresión sigue siendo V; su evaluación hace que V se asigne a V1. Así, la operación [V1 = V2 = expression] es una expresión cuya evaluación:

    • hace que el valor de [expression] se asigne a las variables V1 y V2;
    • devuelve el valor de [expression].

    Esto puede generalizarse a una expresión de la forma [V1 = V2 = ... = Vn = expression].

    El orden de precedencia de los operadores al evaluar una expresión aritmética es el siguiente (de mayor a menor):

    1

    3.4.5.7. Combinación de operadores

    [a = a + b] puede escribirse como [a += b]; [a = a - b] puede escribirse como [a -= b]. Lo mismo se aplica a los operadores /, %, *, <<, >>, >>>, &, |, ^. Así, [a = a / 2;] puede escribirse como [a /= 2;]. Hay una pequeña diferencia: el operador combinado incluye una conversión implícita al tipo de la variable. Si [s] es un [short], [s = s + 1;] se rechaza (el resultado de la suma es un [int]), mientras que [s += 1;] se acepta.

    3.4.5.8. Operadores de incremento y decremento

    La notación [variable++] significa [variable = variable + 1] o [variable += 1]. La notación [variable--] significa [variable = variable - 1] o [variable -= 1]. Cuando se usan en una expresión, estos operadores tienen dos formas:

    • [i++] (posfijo): el valor de la expresión es el valor de i antes del incremento;
    • [++i] (prefijo): el valor de la expresión es el valor de i después del incremento.

    3.4.5.9. El operador ternario ?

    La expresión [expr_cond ? expr1 : expr2] se evalúa de la siguiente manera:

    • Se evalúa la expresión [expr_cond] . Es una expresión booleana;
    • si es verdadera, el valor de la expresión es el de [expr1], y [expr2] no se evalúa;
    • si es falsa, ocurre lo contrario: el valor de la expresión es el de [expr2], y [expr1] no se evalúa.

    La operación [i = (j > 4 ? j + 1 : j - 1);] asignará el valor j+1 a la variable i si j > 4, y j-1 en caso contrario. Es lo mismo que escribir [if (j > 4) i = j + 1; else i = j - 1;], pero más conciso.

    3.4.5.10. Valores nulos: sin operadores especializados

    A diferencia de otros lenguajes como C# o Kotlin, Java no tiene operadores dedicados para el valor [null] (valor de reemplazo, acceso condicional a un miembro). En su lugar, usamos:

    • el operador ternario, [a != null ? a : b], o el método [Objects.requireNonNullElse(a, b)] (Java 9), que devuelve a si no es igual a [null], y b en caso contrario. Se usa para asignar un valor de respaldo: [String name = Objects.requireNonNullElse(IO.readln(), "");];

    • la clase *[Optional] y su método *[map] para acceder a un miembro solo si el objeto existe: [Optional.ofNullable(text).map(String::length)] devuelve un [Optional] vacío si [text] es igual a [null], y un [Optional] que contiene la longitud del texto en caso contrario.

    3.4.5.12. Conversión de tipos

    Es posible, dentro de una expresión, cambiar temporalmente la representación de un valor. Esto se denomina conversión de tipo (type casting). La sintaxis para cambiar el tipo de un valor en una expresión es la siguiente:

    1
    (type) value

    El valor adopta entonces el tipo especificado. Esto produce un cambio en la representación del valor. Se distinguen:

    • las conversiones "de ampliación" (widening), realizadas automáticamente por el compilador: [byte] a [short], [short] a [int], [char] a [int], [int] a [long], [long] a [float] o [double], [float] a [double]... Conservan el orden de magnitud del valor. Las que pasan de un [int] a un [float], o de un [long] a un [float] o a un [double], pueden, sin embargo, perder precisión: un [float] tiene solo 7 dígitos significativos, mientras que un [double] tiene de 15 a 16;
    • las conversiones de reducción (narrowing), que pueden producir una pérdida de información y que el programador debe solicitar explícitamente mediante la notación (tipo): de un [double] a un [int] (se pierde la parte decimal), de un [long] a un [int] (se pierden los bits más significativos), etc.

    Un desbordamiento en un cálculo con enteros o en una conversión entre enteros nunca se notifica: el resultado simplemente es incorrecto. Java no tiene una palabra clave para solicitar una verificación.     3.5.1. Detención

    El método [exit] de la clase [System] permite detener la ejecución del programa:

    1
    System.exit(int status);

    [exit] finaliza el proceso actual y devuelve el control al proceso que lo invocó, normalmente el intérprete de comandos. El valor de [status], conocido como código de retorno, puede ser utilizado por el intérprete de comandos. Por convención, 0 indica que el programa se ejecutó correctamente, mientras que cualquier otro valor señala un error. En Windows, el código de retorno está disponible en la variable [%ERRORLEVEL%] en el símbolo del sistema y en la variable [$LASTEXITCODE] en PowerShell; en Linux y macOS, en la variable [$?] del shell. Así, [System.exit(0);] finalizará la ejecución del programa con un código de retorno 0.

    Sin una llamada a [System.exit], un programa termina con un código de retorno 0 cuando finaliza su método [main], posiblemente con una instrucción [return]. Si termina a causa de una excepción que nadie capturó, muestra esa excepción y finaliza con un código de retorno 1. En Java, el método [main] no puede devolver un entero: [System.exit] es la única forma de especificar el código de retorno.

    3.6. Manejo de excepciones

    Muchos métodos de Java pueden lanzar excepciones, es decir, errores. Cuando un método puede lanzar una excepción, el programador debe manejarla para crear programas más tolerantes a errores: siempre se debe evitar la terminación abrupta de una aplicación.

    3.6.1. La estructura try/catch/finally

    El manejo de excepciones sigue este patrón:

    1
2
3
4
5
6
    try {
    code likely to throw an exception
} catch (Exception e) {
    handle the exception e
}
next statement

    Si el código del bloque [try] no lanza una excepción, la ejecución continúa con la siguiente instrucción; de lo contrario, la ejecución pasa al cuerpo del bloque [catch] y luego a la siguiente instrucción. Observe los siguientes puntos:

    • [e] es un objeto de tipo [Exception] o de un tipo derivado. Hay muchos tipos de excepciones: [ArrayIndexOutOfBoundsException], [NumberFormatException], [ArithmeticException], [IllegalArgumentException], [NullPointerException], [IOException], etc. Al escribir [catch (Exception e)], se indica que se desea manejar todos los tipos de excepciones.     try {
    code likely to throw the exceptions

    handle the exception e1
} catch (NumberFormatException e2) {
    handle the exception e2
}
next statement

    Las cláusulas [catch] se evalúan en orden; se ejecuta la primera cuyo tipo coincide con la excepción. Por lo tanto, una cláusula que maneja un tipo de excepción específico debe preceder a una que maneja un tipo más general: el compilador rechaza una cláusula que nunca podría alcanzarse;

    code likely to throw an exception

    handle the exception e
} finally {
    code executed after try or catch
}
next statement

    Ocurra o no una excepción, el código de la cláusula [finally] siempre se ejecuta. Esta cláusula se usaba para cerrar un archivo; veremos que ahora existe una forma más simple, el [try] con recursos;

    • en la cláusula [catch], puede que no se quiera usar el objeto de excepción. Sin embargo, hay que darle un nombre: desde Java 22, se puede escribir [catch (NumberFormatException _)], donde el carácter _ designa una variable anónima que no se usará;

    3.6.5. Excepciones verificadas y no verificadas

    Esta es una característica importante de Java. Las excepciones son objetos cuyas clases forman una jerarquía:

    • la clase raíz es [Throwable];
    • la clase [Error] y sus subclases indican problemas graves de la máquina virtual ([OutOfMemoryError], [StackOverflowError]...), que un programa normalmente no intenta capturar;
    • la clase [RuntimeException] y sus derivadas ([NullPointerException], [ArithmeticException], [ArrayIndexOutOfBoundsException], [IllegalArgumentException], [NumberFormatException]...) indican por lo general errores de programación o datos incorrectos;
    • las demás clases derivadas de [Exception] ([IOException], [InterruptedException], [ParseException], [SQLException]...) informan de incidentes causados por el entorno del programa (archivo inexistente, caída de la red, base de datos fuera de servicio) que un programa correcto debe prever.

    Las excepciones de esta última categoría se denominan "excepciones verificadas" (checked): el compilador comprueba que un método capaz de lanzar una de ellas, ya sea directamente o al llamar a otro método, la capture mediante una cláusula [catch] o la declare en su firma con la palabra clave [throws]:

    1
    String readFile(String name) throws IOException { ... }

    La responsabilidad se transfiere entonces a los métodos que lo llaman. Las excepciones derivadas de [RuntimeException] y de [Error] se denominan "no verificadas" (unchecked): pueden capturarse, pero el compilador no lo exige y no es necesario declararlas. Muchos otros lenguajes, como C# o Kotlin, solo tienen excepciones no verificadas.

    3.6.6. Liberación de recursos: el bloque try con recursos

    Un recurso (un archivo abierto, una conexión de red, una conexión a una base de datos) debe cerrarse después de su uso, incluso si se produce un error mientras se utiliza. Antes de Java 7, se cerraba dentro de una cláusula [finally], lo que requería varias líneas de código complejo. Java 7 introdujo la instrucción try-with-resources:

    1
2
3
    try (Type resource = ...) {
    use of the resource
}

    El recurso declarado entre paréntesis se cierra automáticamente (mediante una llamada a su método [close()]) cuando termina el bloque, ya sea que finalice normalmente o a causa de una excepción. El tipo del recurso debe implementar la interfaz [AutoCloseable], que contiene únicamente el método [close()]; este es el caso de todas las clases de Java para archivos, red y bases de datos. Se pueden declarar varios recursos, separados por punto y coma: se cierran en el orden inverso al de su apertura. Un [try] de este tipo puede tener cláusulas [catch] y [finally] , que se ejecutan después de cerrar los recursos.

    Java 7 también introdujo multi-catch: una sola cláusula [catch] puede tratar varios tipos de excepción separados por el carácter |: [catch (NumberFormatException | ArithmeticException e)]. Los tipos enumerados no deben derivar unos de otros.

    3.9. Enumeraciones

    Una enumeración es un tipo de datos cuyo dominio de valores consiste en un conjunto de constantes con nombre. Consideremos un programa que debe manejar calificaciones de exámenes. Hay cinco calificaciones posibles: Aprobado, Bastante bien, Bien, Muy bien y Excelente. Podemos entonces definir una enumeración para estas cinco constantes:

    1
    enum Honours { PASS, FAIRLY_GOOD, GOOD, VERY_GOOD, EXCELLENT }

    Por convención, los nombres de las constantes se escriben en mayúsculas. Se puede declarar una variable que tome sus valores de la enumeración:

    1
        Honours myHonours = Honours.PASS;

    Se puede comparar una variable con los distintos valores posibles de la enumeración mediante el operador ==:

    1
2
3
        if (myHonours == Honours.PASS) {
        IO.println("Could do better");
    }

    A diferencia de otros lenguajes en los que una enumeración es simplemente un conjunto de enteros con nombre, una enumeración de Java es una clase, derivada de la clase [java.lang.Enum], cuyos únicos objetos son las constantes declaradas. Cada constante es un objeto único, creado una vez por todas; por eso se pueden comparar con ==. Cada constante conoce su nombre ([name()], o [toString()]) y su número de orden en la declaración ([ordinal()], a partir de 0). El compilador agrega dos métodos estáticos a cada enum:

    • [Honours.values()] devuelve el arreglo de constantes de la enumeración [Honours], en el orden en que fueron declaradas;
    • [Honours.valueOf(name)] devuelve la constante llamada [name], y lanza una [IllegalArgumentException] si ninguna constante tiene ese nombre.

    Una enumeración no se puede convertir a un entero, ni un entero a una enumeración: hay que usar [ordinal()] y [values()].

    changeInt(age);

    Aquí, en la instrucción de la línea 2, [age] es el parámetro real que transmitirá su valor al parámetro formal [a]. Nos interesa saber cómo un parámetro formal obtiene el valor de un parámetro real.

    3.10.1. Paso por valor: el único modo de paso de parámetros de Java

    Java solo tiene un modo de paso de parámetros: el paso por valor. El valor del parámetro real se copia en el parámetro formal correspondiente. Son dos entidades distintas: si el método modifica el parámetro formal, el parámetro real permanece sin cambios.

    Cuando el parámetro es de un tipo por referencia (un arreglo, un objeto), el valor copiado es la referencia: el parámetro formal y el parámetro real hacen entonces referencia al mismo objeto. Por lo tanto, el método puede modificar este objeto, si es modificable, y el llamador verá el cambio; sin embargo, no puede hacer que la variable del llamador haga referencia a otro objeto.

    A diferencia de otros lenguajes, Java no admite el paso por referencia, en el que el parámetro formal y el parámetro real serían una sola y misma variable: un método no puede modificar una variable local de su llamador, ni "devolverle" resultados a través de sus parámetros. En su lugar, se utiliza:

    • el valor de retorno del método, que el llamador asigna a su variable;
    • un record cuando el método necesita devolver varios valores;
    • un arreglo o un objeto mutable pasado como parámetro, en el que el método deposita sus resultados.

    Además, a un parámetro declarado como [final] no se le puede asignar un nuevo valor dentro del método: el compilador garantiza así que conserve el valor transmitido por el llamador.

void main() {
    // 1 - paso por valor: el parámetro real no se modifica
    int age = 20;
    changeInt(age);
    IO.println("Actual parameter age=" + age);

    // 2 - para modificar una variable del llamador: el método devuelve el nuevo valor
    int age2 = 20;

    IO.println("Actual parameter age2=" + age2);

    Conversion c1 = convert("123");
    Conversion c2 = convert("12x");
    IO.println("c1=" + c1 + ", c2=" + c2);
    if (c1.succeeded()) {
        IO.println("value of c1: " + c1.value());
    }

    // 4 - un intercambio de valores: los valores se almacenan en un arreglo
    int[] xy = {1, 2};
    swap(xy);
    IO.println("after swap: x=" + xy[0] + ", y=" + xy[1]);

    // 5 - un arreglo pasado por valor: se copia su referencia
    int[] array = {1, 2, 3};
    modifyArray(array);
    IO.println("array=" + Arrays.toString(array));

    StringBuilder message = new StringBuilder("Hello");

    IO.println("message=" + message);

    BigDecimal price = new BigDecimal("100");

    3.10.2. Sobrecarga de métodos, número variable de parámetros

    Java no tiene parámetros opcionales con valores predeterminados, ni argumentos con nombre. El equivalente de los parámetros opcionales se obtiene mediante la sobrecarga de métodos: varios métodos pueden tener el mismo nombre si sus listas de parámetros difieren en el número o el tipo de parámetros; el compilador selecciona el adecuado según los parámetros reales proporcionados. Lo más habitual es que las versiones cortas llamen a la versión completa, pasándole valores predeterminados. Cuando hay muchos parámetros opcionales, se prefiere un objeto de configuración o un "builder"; veremos ejemplos de ellos más adelante en el curso.

    Java 5 introdujo los métodos con un número variable de parámetros ("varargs"): el último parámetro formal se declara con puntos suspensivos, [int... numbers]. El llamador puede pasar un arreglo o una lista de valores (que puede estar vacía), que el compilador organiza en un arreglo; dentro del método, el parámetro es un arreglo.

    3.11. Funciones locales y tuplas: soluciones en Java

    3.11.1. Métodos, lambdas y clases locales

    Algunos lenguajes permiten definir una función local, es decir, una función escrita dentro de otra función y utilizable solo en ese contexto. Java no lo permite. En nuestros archivos compactos, los métodos del archivo cumplen esta función; en una clase, escribimos métodos privados. Dentro de un método, disponemos de dos herramientas:

    • una lambda (Java 8), una pequeña función anónima que se almacena en una variable de un tipo adecuado, denominado interfaz funcional: [IntUnaryOperator cube = x -> x * x * x;]. Las lambdas se tratan en el capítulo 7, "Interfaces funcionales, lambdas y eventos". Una lambda puede leer las variables locales que la rodean, pero solo si nunca se modifican (variables [final] o "efectivamente finales"); no puede modificarlas;
    • una clase local, declarada dentro del método y utilizable solo dentro de este.

    3.11.2. Records en lugar de tuplas

    Otros lenguajes tienen tuplas, que agrupan varios valores sin necesidad de declarar un tipo. Java no las tiene: utiliza records (Java 16). La declaración [record Couple(int number, String name) {}] crea, en una sola línea, una clase en la que cada objeto consta de un entero y una cadena, junto con un constructor, los métodos de acceso [number()] y [name()], y los métodos [toString()], [equals()], y [hashCode()]. Un record puede declararse dentro de un método (record local). Sus componentes pueden extraerse mediante un patrón de record (Java 21), con el operador [instanceof] o dentro de un [switch]. Los records son la forma natural de hacer que un método devuelva varios valores; como sus componentes tienen nombre, son más legibles que las tuplas.

            total += value;
        }

    acc.add(8);
    IO.println("total=" + acc.total);
